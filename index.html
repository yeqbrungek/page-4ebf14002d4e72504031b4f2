客户端接入规格与兼容层

Tblack 本身不分发闭源私有客户端，用户可通过通用开源内核及主流配置工具完成标准订阅拉取。

桌面端环境 (Desktop)

适用于 Windows、macOS 与 Linux 工作站。支持通过 Clash Verge、Clash Meta 或 v2rayN 等通用客户端载入 YAML 格式的订阅映射配置。

移动终端 (Mobile)

适用于 iOS 与 Android 系统。iOS 推荐使用 Shadowrocket、Loon 或 Quantumult X；Android 平台建议通过 Clash Meta for Android 或 sing-box 实施托管更新。

网关与路由 (Gateway)

支持部署于 OpenWrt、软路由及嵌入式网络设备。依托透明代理组件完成局域网分流，请确保内网设备并发数不超出方案设定的硬件上限。

标准接入作业步骤

请按下列技术规程顺序执行节点配置与路由验证。

STEP 01
获取订阅源串
确认账户有效性并导出对应协议的 URI 链接，避免直接暴露包含密钥的明文地址。
STEP 02
解析配置载荷
在客户端内添加托管链接，同步节点列表与分流规程，完成证书链及端口校正。
STEP 03
确立路由策略
按需切换为规则分流（Rule-based）或全局模式，防止局域网内地址被非预期转发。
STEP 04
联通性测试
执行 ICMP/TCP 延迟探测与 DNS 泄漏检测，验证通道建立状态是否符合运行指标。

常见问题解答

关于流量核算、节点连通故障及多终端限制的运维备忘。

月度流量的重置机制与计费周期如何界定？

所有订阅层级的流量额度均按订购日起算或固定自然月区间计算（以系统控制台实际账单周期为准）。在对应周期结束前未消耗完毕的数据量将自动失效，不予结转至次月。

超出方案限制的最大在线设备数会产生何种结果？

服务端依据并发 IP 建立的会话连接数进行动态限流。当在线终端超过规格上限（例如基础版超过 3 台），后接入的设备将触发握手超时错误，直到既有连接释放。

节点出现大范围握手失败或无法连接时如何自检？

首先请检查客户端本地系统时间是否与标准网络时间同步，时间误差超过 60 秒会导致部分加密传输握手失败。其次可尝试重新拉取最新订阅地址以刷新节点端口及动态解析记录。

如何选择中继节点以满足低延迟交互需求？

旗舰版与团队版提供优化的 IPLC 专线路由，规避公网波动影响。在客户端策略组中选择标有专线标识的分组，并关闭可能导致回环的重复加密配置。
